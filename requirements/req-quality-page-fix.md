# 需求文档：数据质量检查页面改进（#150 修正）
创建时间：2026-05-07
状态：待开发
关联 Issue: #150

## 背景

#150 当前实现仍使用「检查区间段」按钮直接触发 POST /api/quality/check，未做查询/检验分离，也未持久化检查结果。

## 目标

1. 检验结果按天存入数据库，查询时读库不重复检查
2. 两个按钮：查询（读库）vs 触发检验任务（检查后写库）
3. 按钮布局：日期区间 + 查询按钮（紧挨）+ 触发检验按钮（行最右）

## 数据存储

检查结果按天存储，每天一条记录：

| 字段 | 类型 | 说明 |
|------|------|------|
| check_date | DATE | 检查日期（主键） |
| stock_count | INT | 检查股票数 |
| kline_covered | INT | K线有数据的股票数 |
| kline_missing | INT | K线无数据的股票数 |
| report_json | TEXT | 完整报告 JSON |
| created_at | DATETIME | 创建时间 |

## 涉及文件

- `modules/models.py` — 新增 QualityCheckRecord 表
- `web_app.py` — /quality 路由、API 端点
- `static/` 质量检查前端代码

## 页面布局

```
检查区间段：[开始日期] [结束日期] [查询]                    [触发检验任务]
[趋势分析图 — 与上方查询联动，无需独立日期控件]
```

- 查询按钮：紧挨日期区间右侧
- 触发检验任务按钮：同一行最右侧
- 趋势分析图：区间跟随上方日期，查询后自动刷新

## 按钮行为

### 查询按钮
- 根据日期区间查询 QualityCheckRecord 表
- 有记录 → 展示表格和报告
- 无记录 → 显示「该区间无检查记录，请点击触发检验任务」

### 触发检验任务按钮
- 遍历区间内每一天
- 已检查过的日期跳过
- 未检查的日期 → 执行检查 → 结果写入 QualityCheckRecord
- 完成后刷新展示

## 验收标准

- [ ] 新增 QualityCheckRecord 表，按天存储
- [ ] 查询按钮只读数据库，不触发检查
- [ ] 触发检验按钮 → 执行检查 → 写库 → 展示
- [ ] 已检查过的日期不重复检查
- [ ] 两个按钮在同一行：查询在日期右侧，触发在行最右
- [ ] 趋势分析图与上方查询联动，不使用独立日期控件
