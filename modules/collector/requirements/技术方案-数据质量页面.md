## 数据库设计

```sql
CREATE TABLE data_quality_report (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    check_time DATETIME NOT NULL COMMENT '检查时间',
    data_category VARCHAR(32) NOT NULL COMMENT 'stock_basic|kline_daily|realtime_quote',
    total_score DECIMAL(5,1) NOT NULL COMMENT '总分(0-100)',
    completeness_score DECIMAL(5,1) NOT NULL COMMENT '完整度分数',
    freshness_score DECIMAL(5,1) NOT NULL COMMENT '新鲜度分数',
    anomaly_score DECIMAL(5,1) NOT NULL COMMENT '异常检测分数(100=无异常)',
    completeness_detail JSON COMMENT '各字段覆盖率明细',
    freshness_detail JSON COMMENT '新鲜度明细(last_update/days_lag)',
    anomaly_detail JSON COMMENT '异常明细列表',
    status VARCHAR(16) DEFAULT 'ok' COMMENT 'ok|warning|critical',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_category_time (data_category, check_time DESC)
) COMMENT='数据质量检查报告';
```

## 质量评分算法

### 完整度评分

```
per-field rate = 有值记录数 / 总记录数
completeness_score = avg(所有字段的 rate) × 100
```

### 新鲜度评分

```
days_lag = 当前日期 - 最新数据日期
freshness_score = max(0, 100 - days_lag × 5)  // 每滞后1天扣5分
如果非交易日且 days_lag <= 2: 不扣分
```

### 异常检测评分

```
anomaly_count = 所有异常记录数
anomaly_rate = anomaly_count / total_checked
anomaly_score = max(0, 100 - anomaly_rate × 1000)  // 每1%异常扣10分
```

### 总分

```
total_score = completeness_score × 0.4 + freshness_score × 0.3 + anomaly_score × 0.3
```

## API 接口规范

### GET /api/quality/report

返回最近一次质量分析结果。

```
?category=stock_basic  (可选，筛选类别)
```

返回：
```json
{
  "check_time": "2026-05-03 15:00:00",
  "reports": [
    {
      "data_category": "stock_basic",
      "total_score": 65.5,
      "completeness_score": 60.0,
      "freshness_score": 85.0,
      "anomaly_score": 95.0,
      "completeness_detail": {...},
      "freshness_detail": {...},
      "anomaly_detail": {...},
      "status": "warning"
    },
    ...
  ]
}
```

### POST /api/quality/check

触发一次全量质量检查。完成后自动更新 `data_quality_report` 表 + WebSocket 广播结果。

无需参数。返回同上。

### GET /api/quality/history

返回最近 N 次历史检查记录。

```
?category=stock_basic&limit=20
```

## 风险点

| 风险 | 缓解 |
|------|------|
| 全量质量检查耗时较长（11K+ 条） | 异步执行 + WebSocket 推送进度 |
| 异常检测阈值可能不准确 | 阈值可配置（config.py） |
| 前端看不到质量页 | 侧边栏新增导航项 |
