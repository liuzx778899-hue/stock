# 需求文档：数据质量页面

创建时间：2026-05-03
状态：待开发
PM Agent 输出

---

## 背景

当前项目已采集大量数据（股票基础信息 11,360 条 / K线 101,752 条 / 实时行情 16,533 条），但缺少对数据质量的系统性监控：
- 不知道哪些字段缺失严重
- 不知道数据是否过时
- 不知道采集结果是否有异常值
- 字段覆盖率报告（T7-2）已有但独立分散，不成体系

## 目标

新增「数据质量」独立页面，集中展示所有数据的质量分析结果，支持手动检查和采集后自动更新。

## 用户故事

- 作为数据使用者，我希望打开数据质量页面就能看到最新的质量评分，判断数据是否可信
- 作为系统管理员，我希望能手动触发质量检查，验证最近采集的数据
- 作为运维人员，我希望每次采集完成后自动刷新质量报告，不需要自己记住去检查

---

## 功能需求

### 核心功能（必须做）

- [ ] **F1：数据质量页面（侧边栏新增导航）**
  - 页面一打开就显示最近一次质量分析结果（交互 A）
  - 包含 3 个数据类别各自的评分卡片

- [ ] **F2：手动触发质量检查（交互 B）**
  - 页面提供「开始检查」按钮
  - 点击后对所有 3 类数据执行全面质量分析
  - 检查完成后刷新页面显示最新结果

- [ ] **F3：采集完成后自动更新（交互 C）**
  - 任意采集任务完成后，自动触发质量分析
  - WebSocket 推送质量更新通知到前端

- [ ] **F4：三个质量维度**
  - **完整度**：每个字段有值的比例（覆盖率%）
  - **新鲜度**：最近采集时间、数据滞后天数
  - **异常检测**：价格异常、涨跌幅异常、成交量为零、重复记录

- [ ] **F5：质量分析结果落库**
  - 新增 `data_quality_report` 表
  - 每次质量分析结果持久化存储
  - 页面打开时读库展示最近一次结果
  - 手动触发后更新库中记录

- [ ] **F6：质量评分可视化**
  - 每类数据一个总分（0-100）
  - 每个维度一个子分数 + 颜色标识（绿>80 / 黄>60 / 红<=60）
  - 异常信息列表展示

### 扩展功能（有时间再做）

- [ ] **F7：质量趋势图** — 多次检查结果的时间序列折线图
- [ ] **F8：按数据源维度的质量对比** — 不同数据源的质量差异

## 不做的事

- 不做自动修复（只发现问题，不修改数据）
- 不做数据一致性校验（跨源比较）
- 不做实时监控告警（消息推送）

## 验收标准

- [ ] 侧边栏能看到「数据质量」导航，点击进入质量页面
- [ ] 页面打开后能看到 3 类数据 × 3 个维度的评分
- [ ] 点击「开始检查」按钮后，评分更新（非缓存数据）
- [ ] 采集任务完成后，质量报告自动更新
- [ ] 数据库 `data_quality_report` 表有检查记录
- [ ] 刷新页面后评分不丢失（从数据库恢复）
